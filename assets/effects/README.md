# Issue #8 エフェクト素材

Issue #8「キャラクターがマスのタイプに応じて道を攻撃・塗装して移動する演出を追加する」用の素材候補です。

## 採用形式

- 本番入力: 透明RGBAのPNGスプライトストリップ
- 確認用: アニメーションWebP
- 色: PNGの不透明部分をマスクとして使い、実行時に選択色へ着色する
- 基準方向: 右向き
- 上下左右: キャラクター本体は回転せず、攻撃・移動尾・跳弾だけをルートの接線方向へ回転する
- 折り返し: 長いエフェクト画像を曲げず、ルート描画と `ricochet` の接触素材を組み合わせる

色付きWebPを本番素材にしない理由は、選択色・白・将来の柄へ正確に追従させるためです。WebPは動きの確認にだけ使用します。

## スプライト規格

原則として全ファイルを次の規格へ統一しています。

- 画像サイズ: 2172 × 724 px
- フレーム数: 3
- 1フレーム: 724 × 724 px
- 配置: 左から `予備動作 / 最大形 / 収束または反動`
- 背景: 透明
- 色: 白〜薄いグレー
- 再生目安: 90 ms / 110〜130 ms / 180〜220 ms

`landing-splash-mask-strip-v1.png` は6段階を1枚へ収めた初期試作です。セルが正方形ではないため本番対象外とし、3フレームへ整理した `landing-splash-mask-strip-v2.png` を使用します。

## 素材一覧

| ファイル | 用途 | 実装上の扱い |
|---|---|---|
| `shot-mask-strip-v1.png` | SHOTの粒弾と小さな着弾 | 3発を時間差でルート上へ進める |
| `beam-cap-mask-strip-v1.png` | BEAMの溜め・先端 | 長い線はルートをなぞる描画で作り、先端だけを重ねる |
| `wave-mask-strip-v1.png` | WAVEの扇状波 | 進行方向へ回転し、幅を広げて消す |
| `bomb-mask-strip-v1.png` | BOMBの色玉と円形着弾 | 色玉は弧を描いて移動し、3コマ目で塗装を確定する |
| `burst-mask-strip-v1.png` | BURSTの太いインク帯 | 太いルート描画の先端へ重ねる |
| `ricochet-mask-strip-v1.png` | Uターン接触・潰れ・再発射 | Uターン頂点で一度だけ表示し、前後の接線へ合わせる |
| `move-tail-mask-strip-v1.png` | キャラクター移動尾 | 本体の背後へ配置し、進行方向の反対側へ伸ばす |
| `landing-splash-mask-strip-v2.png` | 最終マスの着地飛沫 | 方向には依存させず、キャラクターの下へ表示する |

`previews/` 内のWebPは、上記PNGから切り出した3フレームを無限ループさせた確認用です。

ファイル名・コマ数・再生時間・攻撃割り当ては `manifest.json` にまとめています。実装では同じ値をコードへ重複して書かず、このマニフェストを読み込むか、読み込み失敗時だけ同内容の既定値へフォールバックします。

## 攻撃ごとの描画分担

長さや曲がり方がルートによって変わるため、攻撃全体を1本の動画にはしません。

- SHOT: PNGの粒を3つ生成し、同じルートを時間差で進める
- BEAM: 道の中心線を細いストロークで塗り、先端へPNGを配置する
- WAVE: PNGを進行方向へ回転し、短い範囲で拡大する
- BOMB: PNGの色玉を現在マスから塗装開始点へ弧状移動させる
- BURST: 道の中心線を太いストロークで一気に伸ばし、先端へPNGを配置する
- RICOCHET: Uターン地点で接触PNGを再生してから、次の接線へ続ける

この分担なら、直線・上下移動・左右移動・Uターンを同じ素材で処理できます。

## マス・武器カテゴリから攻撃タイプへの割り当て

Issue #8の5種類を既存データへ曖昧なく割り当てるため、次を初期値とします。公式武器の形や固有弾道は再現せず、`data/raw-manifest.json` にある大分類だけを判定へ使います。

| 現在マス | 既存カテゴリ | 攻撃タイプ |
|---|---|---|
| START | `start` | SHOT（初回用の中立動作） |
| メイン | `shooter` / `maneuver` / `blaster` | SHOT |
| メイン | `charger` / `spinner` / `stringer` | BEAM |
| メイン | `roller` / `brush` / `wiper` | WAVE |
| メイン | `slosher` | BOMB |
| メイン | `shelter` | BURST |
| サブ | `sub` | BOMB |
| スペシャル | `special` | BURST |
| GOAL | `goal` | 攻撃しない |

移動開始時にこの結果を1回だけ確定し、途中のマスでは再判定しません。メイン武器では、画像パスのファイル名を解析せず、raw manifestの `weaponNameJa -> category` 対応を使用します。

## キャラクター素材との分担

既存の `assets/player/` を次のように使用します。

- 待機: 既存4フレームのidle strip
- 溜め・反動: 正面向き本体へ拡大縮小を加える。新しい方向別キャラクター画像は作らない
- 移動: 正面向き本体をルート上で平行移動し、`move-tail` を別レイヤーで重ねる
- 着地: 正面向き本体を一度潰し、`landing-splash` を下へ重ねる
- 色替え: body-maskを選択色へ着色し、light/dark-detailsを上へ重ねる

スライム・イカ型・タコ型の違いは、画像の向きではなく変形の強さと基準点で表現します。

| キャラクター | WINDUP | 反動 |
|---|---|---|
| スライム | 全体を横へ約1.12倍、縦へ約0.84倍 | 下側を基準に弾む |
| イカ型 | 頭部側を縦へ圧縮 | 上端が一度伸びて戻る |
| タコ型 | 下側を横へ広げる | 脚側を先に戻し、本体が少し遅れて戻る |

## 推奨タイミング

| 状態 | 目安 |
|---|---:|
| WINDUP | 160〜220 ms |
| ATTACK | 240〜360 ms |
| PAINT | 1区間あたり45〜70 ms、合計は最大500 ms程度 |
| MOVE | 1区間あたり既存値に近い140〜160 ms |
| LANDING | 300〜440 ms |

長い出目でも待ち時間が増えすぎないよう、PAINTは区間数に比例させつつ上限を設けます。MOVEは現在位置を追える速さを維持します。

`prefers-reduced-motion` では、攻撃と移動の軌跡アニメーションを省略し、塗装状態を即時更新したあと短い着地表示だけを行う想定です。

## 状態遷移と境界条件

- `0` マス移動: 攻撃・塗装・移動・着地を再生しない
- GOALを越える出目: 出目そのものではなく、GOALまでの実移動区間だけを攻撃・塗装する
- 攻撃タイプ: 移動開始時の現在マスから1回だけ決定する
- 色: 移動開始時の選択色を使用する。アニメーション中は色・表示設定・進行操作を変更不可にする
- Undo: 通常の逆再生攻撃は行わず、位置を戻すアニメーション後に論理位置から塗装範囲を再計算する
- レイアウト変更: 塗装済みピクセルを保存せず、現在位置から「何区間通過済みか」を再描画する
- リサイズ: 論理的なアニメーション進捗を維持し、最新のルート座標へ描画し直す
- タブ非表示: 固定回数のタイマーではなく経過時間を基準にし、復帰時に途中状態が残らないようにする
- 連打防止: `WINDUP` から `LANDING` の終了までサイコロ、手入力、Undo、再生成をロックする

初期版は現在の単色選択へ対応します。将来の柄は `paintStyle` の入力を差し替えられる構造だけを残し、Issue #8の必須範囲には含めません。
